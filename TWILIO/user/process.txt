## 🧠 Objective of the Session

> Build a **video calling system** where a user can join a room and connect their webcam using **Twilio Video SDK**, integrated with **Django**.

---

## 🗺️ HIGH-LEVEL FLOW

```
User (Frontend) → Django (Backend) → Twilio (Video Infra)
             ↘                        ↗
          HTML + JS         Twilio SDK + Token
```

---

## 🧩 COMPONENT BREAKDOWN

### 1. **Twilio Video SDK** (Frontend)
- A JavaScript library that connects to Twilio Video Rooms.
- Handles camera, mic, and connecting users in real-time.

### 2. **Access Token** (Backend)
- A secure token generated by Django using Twilio credentials.
- Token includes:
  - Identity (who’s joining)
  - Room name (where they’re joining)
  - Permissions (Video access)

### 3. **Video Room** (Twilio Infrastructure)
- A virtual space where participants meet.
- Can be peer-to-peer or group-based.
- Twilio manages the media routing.

---

## ⚙️ STEP-BY-STEP PROCESS

### 🔹 Step 1: User Opens the Video Call Page

- A Django view (`video_call`) renders an HTML page (`video_call.html`)
- This page includes the **Twilio SDK** (via a script tag)

### 🔹 Step 2: User Clicks “Join Room”

- JavaScript runs:
  - Collects username (`identity`)
  - Sends a `GET` request to `/token/?identity=Alice&room=demo-room`

---

### 🔹 Step 3: Backend Generates the Access Token

Django view (`generate_token`) does the following:
1. Reads identity & room from query params
2. Uses Twilio credentials (`ACCOUNT_SID`, `API_KEY_SID`, `API_KEY_SECRET`)
3. Generates a JWT access token with a **VideoGrant** for the room
4. Returns the token as a JSON response

**Important Concepts Here:**
- `AccessToken` → JWT
- `VideoGrant` → what the token allows (join a room)
- Identity → unique user ID for each participant

---

### 🔹 Step 4: Frontend Connects Using the Token

Once the token is received:
```js
Twilio.Video.connect(token, { name: "demo-room", video: true, audio: true })
```

- This connects the browser to Twilio’s Video infrastructure
- Camera and mic are activated
- Tracks are displayed in `<video>` elements

---

### 🔹 Step 5: Attach Video Tracks

After connecting, local and remote participants' video tracks are attached:

```js
publication.track.attach()
```

- Each participant’s stream (video/audio) is displayed on the page
- The frontend handles joining/leaving events too

## 📎 TWILIO CREDENTIALS (What You Need)

From Twilio Console:

- **ACCOUNT_SID**
- **API_KEY_SID**
- **API_KEY_SECRET**

You put these in `settings.py` and use them in your views.

## 🔍 SECURITY TIPS

- Always generate tokens on the backend
- Tokens should expire quickly (set TTL)
- Validate `identity` to avoid impersonation
